# How This Website Works

The goal for this website was simple: a static and fast site that could showcase projects and photography without bloating the repository or slowing down the site. But as often happens that is easier said than done.

---

## First Iteration and First Issues



## Templatizing

After a bit of researching, I discovered Eleventy. A static site generator that lets you mix Markdown and Nunjucks templates. It was perfect for this project because it offered flexibility without overcomplicating things.

I set up a project structure with `src` for the content and layouts, `dist` for the generated site, and a few helper folders for images and assets. The layouts provided a consistent header, footer, and navigation, while pages like the home, about, and project sections pulled content from Markdown and Nunjucks templates.

At first, everything was local. Images were stored directly in the repository under `src/photos`, and galleries were generated by reading folders and building a collection in Eleventy. A small Nunjucks shortcode handled responsive images, automatically creating multiple sizes and web-friendly formats like WebP and AVIF.


## Adding Images



## Realizing Repository Size Was a Problem

It didn’t take long to realize that storing high-resolution photography directly in the repo was unsustainable. Every new gallery added hundreds of megabytes, which made the repository unwieldy and slow.

The solution? Move the images to **Cloudflare R2**, a fast and scalable object storage service. This way, the site could fetch images from a CDN, keeping the repository lean and the site performant.

## Automating the Gallery


## Responsive Images and Thumbnails

High-resolution photography looks amazing, but loading huge files for a thumbnail grid would slow the site down. Using `@11ty/eleventy-img`, thumbnails were automatically generated and normalized to consistent dimensions. This made the galleries look tidy, while still giving users the option to view full-resolution images from the CDN.


## Utilizing a CDN

Next came the challenge of making Eleventy automatically discover galleries stored on R2. By connecting to R2 using the AWS S3 client, the site could list all folders under `photos/`, fetch image URLs, and generate gallery pages dynamically.

Each gallery page would show a grid of thumbnails, with links to the full-size images. This step required a bit of finesse—figuring out how to map R2 keys to URLs and ensuring the Nunjucks templates could handle remote images—but once it worked, it made adding new galleries as simple as uploading files to R2.

## Merging Auto-Discovery and the CDN



## Building and Deploying with GitHub Actions

Once the site was generating galleries correctly, it was time to automate the build and deployment process. Using **GitHub Actions**, the workflow:

1. Checks out the repository.
2. Installs dependencies.
3. Runs Eleventy to generate the site into `dist/`.
4. Deploys the `dist/` folder to GitHub Pages.

Secrets for R2 credentials are stored securely in GitHub, and environment variables ensured the build process could access the correct bucket and CDN URLs. After some troubleshooting with environment variables and permissions, everything started building and deploying automatically on each push.

---

## The Result

After all the pieces came together:

* The **home page** displayed projects and a link to projects and galleries.
* **Projects** could easily be added utilizing templates for the article wrapping.
* The **galleries page** listed all albums dynamically.
* Clicking on a gallery opened a dedicated page with thumbnails that linked to full-resolution images on R2.

In short, the site became a dynamic portfolio that could showcase both development projects and photography, while remaining fast, lightweight, and easy to maintain.

---

## Lessons Learned

1. Hosting high-resolution images in a repository is a quick path to bloat. Using a CDN or object storage is essential for portfolios.
2. Automating gallery discovery saves time, especially for a photographer constantly adding new work.
3. Eleventy and Nunjucks provide enough flexibility to handle complex workflows like image optimization, remote hosting, and dynamic templates.
4. CI/CD workflows with GitHub Actions streamline deployment and reduce manual effort.

---

This project was a blend of design, automation, and performance optimization. From Eleventy templates to Cloudflare R2 and GitHub Actions, each piece worked together to create a portfolio that’s both beautiful and practical.
